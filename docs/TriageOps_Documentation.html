TriageOps — DevOps Incident Triage Agent

Paste a server, Docker or Kubernetes error. TriageOps classifies it, finds the likely root cause with evidence from your input, suggests safe fix commands, rates its own confidence, and produces an incident report. It suggests, never executes.

Python 3.11+FastAPIPydantic v2 Gemini / Vertex AIBM25 retrievalTyper CLI Streamlit + Web UI46 unit tests · 47 golden rules

1. Project Overview

TriageOps was designed for the Rival.io Forward Developer assessment (see the design document in the repo root). The assignment asked for an Agent (Task 1) and a multi-step Workflow (Task 2, bonus). This repo implements both as one codebase: the 7-step pipeline is the workflow, and the analyst step is the standalone troubleshooting agent.

The problem it solves

When infrastructure breaks, engineers lose time reading logs and guessing causes; juniors sometimes run destructive commands. TriageOps gives a fast, structured, safety-aware first response for three areas: Linux servers, Docker, Kubernetes. Anything else (billing, app business logic, poems) is politely declined.

Design principles

1. Suggest, never execute

No command is ever run. Humans decide.

2. Evidence over guessing

Root causes must cite lines from the input.

3. Honest uncertainty

High/Medium/Low confidence plus what info would raise it. Vague input → clarifying questions.

4. Code wins over the model

Secrets, scope gating and risky-command detection are deterministic code, not LLM judgement.

5. Predictable output

Every LLM reply is validated against a Pydantic schema.

6. Small & well-tested

Unit tests need no API key; golden tests score end-to-end behaviour.

4. Safety Design

sequenceDiagram participant U as User input participant S as safety.py participant L as LLM provider participant R as Report U->>S: raw text (may contain secrets) S->>S: redact_secrets() — regex, 10 patterns S->>L: only redacted text leaves the process L-->>S: fix_steps (model's own risk labels) S->>S: review_commands() — 15 risky patterns S->>R: warnings + risk forced to "high" (code overrides model)

Secret patterns redacted (10)

AWS access key, AWS secret key, private key blocks, GitHub tokens, GCP service-account JSON, Bearer tokens, credentials in URLs, generic password/token/api_key= assignments, 32+ char hex strings, 40+ char base64 strings. A connection-string pattern (postgres://, redis://…) is warn-only because it is too noisy to auto-redact.

Risky command patterns (15) — each carries a reason and a safer alternative

PatternWhy riskySafer alternative offered
rm -rfIrreversible deleteinteractive rm -ri / trash first
kubectl delete ns|pv|pvc|nodeMass resource/data lossinspect with get/describe; cordon + drain
docker system prune, docker rm/rmi -fRemoves volumes/in-use itemsfiltered prune; stop then remove
--forceSkips safety checksdry-run / describe first
kill -9No graceful shutdownkill -15 first
chmod -R 777Opens permissions to allleast privilege (755)
mkfs, dd if=Destroys disk dataverify device with lsblk, back up
DROP TABLE/DATABASE/SCHEMAPermanent DB losstransaction + ROLLBACK test, backup
kubectl exec … -- shShell in prod containerkubectl debug on a copy
systemctl stop|disable nginx/sshd/docker/kubeletStops critical servicecheck status/logs first
Honest limitation: both detectors are regex heuristics. They catch common patterns, not every possible secret or destructive command. This is stated in the README and in safety.py.

5. LLM Layer & Providers

All model interaction lives in llm.py. The rest of the code only calls complete_json(system_prompt, user_message, schema).

flowchart TD CJ["complete_json(prompt, msg, Schema)"] --> ENR["Append JSON schema to system prompt"] ENR --> CM["_call_model()"] CM --> P{"_get_provider()"} P -- "TRIAGEOPS_FORCE_OFFLINE=1" --> OFF["Offline heuristic engine"] P -- "GEMINI_API_KEY set" --> GA["Gemini API (google-genai)"] P -- "GOOGLE_CLOUD_PROJECT set" --> VX["Vertex AI"] P -- "nothing set" --> OFF GA -- "exception" --> OFF VX -- "exception" --> OFF GA --> VAL VX --> VAL OFF --> VAL["Strip ``` fences, validate with Pydantic"] VAL -- valid --> RET(["Typed object"]) VAL -- invalid --> RT["Retry once, inject validation error"] RT --> VAL RT -- "still invalid" --> FB["Final fallback: offline engine"]

Offline heuristic engine

Keyword/regex-based classifier and analyst that return schema-valid JSON for the demo scenarios (CrashLoopBackOff, OOMKilled/137, disk full, vague input, out-of-scope). It exists so the app, tests and UI work without any cloud credentials, and acts as a fallback if a provider call fails.

Be aware: offline output is canned for known scenarios and is not real reasoning. For genuine diagnosis of arbitrary input, set GEMINI_API_KEY or GOOGLE_CLOUD_PROJECT. The golden-test pass (47/47) was obtained using the offline engine; it has not been validated against a live model yet.

8. Core Backend Files (src/triageops/)

pipeline.pyCORE

The heart of the project. run_triage(raw_input) executes the 7 steps and returns a Report. At import time it creates a module-level _runbooks singleton (loaded once). Runbook directory resolution order: TRIAGEOPS_RUNBOOKS_DIR env var → <project>/runbooks → ./runbooks.

Notable details: trims to last 400 lines; step 6 merges model fix-commands with commands the user quoted in backticks/quotes so destructive suggestions in the question are caught too.

schemas.pyCORE

All Pydantic v2 models and literal types (see section 6). The JSON schema of these models is injected into the LLM prompt so the model knows the exact shape.

safety.pyCORE

Pure-code safety. Exposes redact_secrets(text) → (clean, found), review_commands(list) → CommandWarning[], is_risky_command(cmd) → bool. Data lives in SECRET_PATTERNS, WARN_ONLY_PATTERNS, RISKY_COMMANDS — add new rules by appending to these.

llm.pyLLM

Provider router (Gemini API → Vertex AI → offline), JSON-validated completion with one self-correcting retry, markdown-fence stripping, and the offline heuristic engine (_offline_classification, _offline_analysis). Env: GEMINI_API_KEY, GOOGLE_CLOUD_PROJECT, GOOGLE_CLOUD_LOCATION, TRIAGEOPS_MODEL, TRIAGEOPS_FORCE_OFFLINE. Temperature is 0.1 for stable structured output.

prompts.pyLLM

Holds CLASSIFIER_SYSTEM and ANALYST_SYSTEM prompts plus build_classifier_user() / build_analyst_user() message builders. Kept separate so prompts can be tuned without touching logic. Analyst rules enforce: never invent log lines, never claim to run commands, flag destructive commands, don't reconstruct [REDACTED] values, Low confidence + questions for vague input, trust evidence over runbooks.

retrieval.pyCORE

Class Runbooks: loads *.md files, tokenises with a simple regex, builds a BM25Okapi index (library rank-bm25). Methods: search(query,k), get_runbook(name), list_runbooks(), len(). Degrades gracefully (returns []) if the library or folder is missing. Design choice: BM25 first; upgrade to embeddings only if golden tests show misses.

render.pyCORE

Deterministic formatting, no LLM. to_markdown(report) builds the postmortem-style document (classification table, summary, root cause + evidence, fix steps with risk badges, safety warnings, verification, prevention, confidence, runbooks, security notes). to_json(report) dumps the model. Declined reports render a short "Out of Scope" page.

logging_config.pyOPS

Console (human-readable) and JSON log formatters, level controlled by TRIAGEOPS_LOG_LEVEL. Called from __init__.py on import.

__init__.pyOPS

Defines __version__ = "0.1.0" and sets up default logging.

9. Interfaces (CLI · API · Streamlit)

cli.pyUI

Typer + Rich app. Three commands:

  • triageops [file] [--json] [--quiet] — reads a file, piped stdin, or interactive paste; prints a rendered markdown report.
  • triageops serve [--host --port --reload] — starts uvicorn with the API and web UI.
  • triageops ui [--port] — launches the Streamlit app.

Exit codes: 1 file not found, 2 pipeline error.

api.pyUI

FastAPI app. Serves the web UI at /, static assets at /static, Swagger at /docs. Has request-latency logging middleware and open CORS (tighten for production). Endpoints in section 14.

ui/app.pyUI

Streamlit interface: sidebar with five example inputs, text area, metric row (type, severity, confidence, secrets, time), expandable security and command-warning panels, markdown/JSON tabs, download buttons. Calls run_triage directly (not via the API).

ui/__init__.pyUI

An earlier draft of the Streamlit app accidentally saved inside the package init. It is redundant with ui/app.py and can be cleaned up (see section 18).

10. Web Command Center (src/triageops/web/)

A dependency-free single-page UI (vanilla HTML/CSS/JS) served by FastAPI. Dark glassmorphic design.

web/index.htmlUI

Left: terminal-style editor with upload/paste/clear, live secret pre-scan banner, run button, 4-stage progress stepper. Right: report area with three tabs (Command Center cards, Markdown, JSON), empty/loading states, and slide-in drawers for runbooks and history.

web/style.cssUI

Design tokens (CSS variables), severity badges (P1 glow red … P4 grey), confidence meter, stepper states, evidence/code blocks, warning cards, drawers, toasts, responsive breakpoints.

web/app.jsUI

Client logic: preset loading, Ctrl/⌘+Enter to run, real-time client-side secret scan, stepper animation, two parallel POST /triage calls (json + markdown), report rendering (escaped with escapeHtml), copy/download tools, runbook drawer (GET /runbooks/{name}), and history persisted to localStorage (last 20).

Note: the stepper animation is cosmetic (timed), because the API returns a single response — it does not reflect true per-step progress. Also, the browser UI has not yet been verified visually in a real browser (the automated browser tool failed to start); API and static routes were verified over HTTP.

17. How to Extend

Add a runbook

Drop topic.md into runbooks/. Auto-indexed.

Add a risky command

Append (regex, reason, safer) to RISKY_COMMANDS in safety.py + a test.

Add a secret pattern

Add to SECRET_PATTERNS; add a test in test_safety.py.

Tune the model

Edit prompts in prompts.py, then run the golden harness with a live key.

Swap provider

Change only _call_model in llm.py.

Add a golden case

New JSON in tests/golden/ with an expect block.

18. Limitations & Known Notes

Solid: pipeline structure, schemas, deterministic safety layer, tests, API, packaging, CI definition.
  • Golden tests were run on the offline engine only. Run python tests/run_golden.py with a real key to measure true model quality.
  • Offline engine is canned for known scenarios; not general reasoning. Its sample fix command for missing env vars contains a placeholder credential-style URL — treat output as a demo.
  • Web UI not browser-verified; verified only via HTTP requests. Stepper is cosmetic; each click calls /triage twice (json + markdown).
  • Redundant file: ui/__init__.py holds an older Streamlit draft; consider deleting it.
  • docker-compose sets TRIAGEOPS_API_URL for the UI, but the Streamlit app calls the pipeline directly and ignores it.
  • Dockerfile/CI were written but not executed locally (no Docker build or Actions run observed).
  • CORS is * and the API has no auth or rate limiting — fine for local use, not for public exposure.
  • Regex secret/command detection is heuristic; the 400-line trim keeps only the tail of long logs.
  • The commit pushed to GitHub (2coolkalamkaar/TriageOps) predates this document; commit docs/ to publish it.
